# Sisyphus 자동화 명령어 시스템 사용법

## 개요

Sisyphus AI 에이전트를 위한 커스텀 명령어 시스템으로, 단 한 줄의 명령어로 완전한 기능을 구현하고 테스트하고 배포할 수 있습니다.

## 명령어 목록

### 1. `/pr` - Pull Request 자동 생성

**설명:** 변경사항을 자동으로 스테이징하고 커밋한 후, 원격 저장소에 푸시하고 PR을 생성합니다.

**사용법:**
```
/pr feature_name="기능 이름" description="상세 설명" changes="변경사항 목록" testing="테스트 내용"
```

**예시:**
```
/pr feature_name="다크모드 토글 추가" description="테마 스위칭 기능 구현" changes="테마 프로바이더 업데이트 및 토글 컴포넌트 추가" testing="브라우저에서 테마 스위칭 테스트 완료"
```

**자동 실행 과정:**
1. Git 상태 확인
2. 변경사항 스테이징 (`git add .`)
3. 커밋 생성 (`git commit -m "feat: ..."`)
4. 원격 저장소에 푸시 (`git push`)
5. GitHub PR 생성 (`gh pr create`)

---

### 2. `/blog` - 블로그 포스트 자동 생성

**설명:** 새로운 블로그 포스트를 프론트매터와 함께 자동으로 생성합니다.

**사용법:**
```
/blog title="포스트 제목" tags="태그1,태그2,태그3" content="초안 내용..."
```

**예시:**
```
/blog title="Next.js 15 신기능 분석" tags="next.js,react,typescript" content="Next.js 15의 새로운 기능들에 대한 분석..."
```

**자동 생성되는 것들:**
- 날짜 기반 파일명 (`2024-01-17-nextjs-15-analysis.md`)
- 프론트매터 (title, date, tags)
- 마크다운 템플릿

---

### 3. `/component` - React 컴포넌트 완전 자동 생성

**설명:** React 컴포넌트와 관련 파일들을 한 번에 생성합니다.

**사용법:**
```
/component name="컴포넌트명" type="타입" props="프롭스 목록" story=true test=true
```

**파라미터:**
- `name`: 컴포넌트 이름 (필수)
- `type`: `component` (기본값), `page`, `layout`
- `props`: `prop명:타입` 형식, 쉼표로 구분
- `story`: Storybook 스토리 생성 여부
- `test`: 테스트 파일 생성 여부

**예시:**
```
/component name="UserProfile" type="page" props="user:User, onEdit:Function" story=true test=true
```

**자동 생성되는 파일들:**
- ✅ React 컴포넌트 (`UserProfile.tsx`)
- ✅ TypeScript Props 인터페이스
- ✅ 테스트 파일 (`UserProfile.test.tsx`)
- ✅ Storybook 스토리 (`UserProfile.stories.tsx`)
- ✅ 인덱스 파일 export 추가

---

### 4. `/api` - API 엔드포인트 완전 자동 생성

**설명:** Next.js API 엔드포인트와 관련 파일들을 한 번에 생성합니다.

**사용법:**
```
/api endpoint="엔드포인트명" method="HTTP메서드" description="설명" auth=true validation=true
```

**파라미터:**
- `endpoint`: API 엔드포인트 이름 (필수)
- `method`: `GET` (기본값), `POST`, `PUT`, `DELETE`
- `description`: API 설명
- `auth`: 인증 미들웨어 추가 여부
- `validation`: 유효성 검사 미들웨어 추가 여부

**예시:**
```
/api endpoint="users" method="GET" description="모든 사용자 정보 조회" auth=true validation=true
```

**자동 생성되는 파일들:**
- ✅ Next.js API 라우트 (`/app/api/users/route.ts`)
- ✅ 비즈니스 로직 핸들러 (`handler.ts`)
- ✅ TypeScript 타입 정의 (`types.ts`)
- ✅ API 테스트 파일 (`route.test.ts`)
- ✅ 인증/유효성 검사 미들웨어

---

### 5. `/test` - 테스트 자동 실행

**설명:** 다양한 옵션으로 테스트를 자동으로 실행합니다.

**사용법:**
```
/test component="컴포넌트명" coverage=true type="테스트타입" watch=true
```

**파라미터:**
- `component`: 특정 컴포넌트만 테스트
- `coverage`: 커버리지 리포트 생성
- `type`: `all` (기본값), `unit`, `integration`, `e2e`
- `watch`: Watch 모드로 실시간 테스트
- `verbose`: 상세한 출력

**예시:**
```
/test component="Button" coverage=true type="unit" watch=true
```

## 실제 사용 시나리오

### 시나리오 1: 새로운 대시보드 기능 개발

```
# 1. 대시보드 페이지 컴포넌트 생성
/component name="Dashboard" type="page" props="data:DashboardData, onRefresh:Function" story=true test=true

# 2. 대시보드 데이터 API 생성
/api endpoint="dashboard" method="GET" description="대시보드 데이터 조회" auth=true validation=true

# 3. 테스트 실행 및 커버리지 확인
/test component="Dashboard" coverage=true

# 4. PR 생성 및 배포
/pr feature_name="대시보드 기능 추가" description="새로운 대시보드 페이지와 API 구현" changes="대시보드 컴포넌트, API 엔드포인트, 테스트 코드 추가" testing="모든 테스트 통과 및 커버리지 90% 이상"
```

### 시나리오 2: 블로그 포스트 작성 및 배포

```
# 1. 블로그 포스트 생성
/blog title="Next.js 15 신기능 분석" tags="next.js,react,typescript" content="Next.js 15의 새로운 기능들에 대한 심층 분석..."

# 2. 관련 컴포넌트 테스트
/test component="blog" coverage=true

# 3. PR 생성
/pr feature_name="블로그 포스트 추가" description="Next.js 15 신기능 분석 포스트" changes="새로운 블로그 포스트 추가" testing="마크다운 렌더링 확인"
```

### 시나리오 3: 사용자 관리 API 개발

```
# 1. 사용자 목록 API 생성
/api endpoint="users" method="GET" description="모든 사용자 정보 조회" auth=true validation=true

# 2. 사용자 생성 API 생성
/api endpoint="users" method="POST" description="새로운 사용자 생성" auth=true validation=true

# 3. 관련 테스트 실행
/test component="users" coverage=true type="integration"

# 4. PR 생성
/pr feature_name="사용자 관리 API 구현" description="사용자 조회 및 생성 API" changes="사용자 엔드포인트, 유효성 검사, 테스트 코드" testing="API 통합 테스트 통과"
```

### 시나리오 4: UI 컴포넌트 라이브러리 확장

```
# 1. 새로운 버튼 컴포넌트 생성
/component name="NeonButton" props="text:string, onClick:Function, variant:primary|secondary" story=true test=true

# 2. 카드 컴포넌트 생성
/component name="GlassCard" props="children:ReactNode, title:string" story=true test=true

# 3. UI 컴포넌트 테스트
/test component="NeonButton" coverage=true type="unit"

# 4. PR 생성
/pr feature_name="UI 컴포넌트 라이브러리 확장" description="NeonButton과 GlassCard 컴포넌트 추가" changes="새로운 UI 컴포넌트, 스토리북 스토리, 단위 테스트" testing="모든 UI 컴포넌트 테스트 통과"
```

## 고급 기능

### 1. 템플릿 기반 코드 생성
- **컴포넌트 템플릿:** UI, Page, Layout 타입별 템플릿
- **API 템플릿:** CRUD, Auth, File upload 패턴
- **테스트 템플릿:** Unit, Integration, E2E 테스트 패턴

### 2. 자동화된 워크플로우
- **개발 사이클:** 코드 생성 → 테스트 실행 → 커밋 → PR 생성
- **품질 검사:** Lint, Type check, Test coverage 자동 검증
- **배포 자동화:** PR 머지 후 자동 배포

### 3. 지능형 파라미터 처리
- **Props 자동 추론:** 타입 기반 Props 인터페이스 생성
- **API 스키마 자동 생성:** 요청/응답 타입 자동 정의
- **테스트 케이스 자동 생성:** 컴포넌트 기반 테스트 케이스 생성


## 팁과 모범 사례

### 1. 명령어 조합
- 여러 명령어를 체인으로 연결하여 완전한 기능 구현
- 테스트 → 커밋 → PR 생성 순서로 자동화

### 2. 파라미터 최적화
- `story=true test=true` 옵션으로 개발 초기부터 문서화와 테스트 확보
- `coverage=true`로 코드 품질 지속적 모니터링

### 3. 타입 안전성
- Props 타입을 명시적으로 지정하여 런타임 오류 방지
- API 타입 정의로 프론트엔드-백엔드 간 인터페이스 명확화

### 4. 테스트 전략
- `type=unit`으로 단위 테스트부터 시작
- `type=integration`으로 컴포넌트 간 연동 테스트
- `coverage=true`로 코드 커버리지 지속적 확인

이제 이 명령어들을 사용하여 **단 한 줄의 명령어로** 완전한 기능을 구현하고 테스트하고 배포할 수 있습니다!
